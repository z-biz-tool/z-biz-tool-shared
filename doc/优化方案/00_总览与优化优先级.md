## 一、这个库的独特价值

z-biz-tool-shared 是 z-biz-tool 系列 10 个桌面应用（db / file / note / knowledge / terminal / sys / box / aigen / pet / agent-worker）唯一的跨项目共享代码库，承载四类本应收敛的能力：

1. **AI 能力中台**（`src/ai/`）：统一 AIConfig / executeAI 入口，避免每个应用各写一套 OpenAI 客户端；
2. **Agent 交互套件**（`src/agent/`）：AgentPanel / SQLEditor / QueryHistoryViewer 等可复用面板；
3. **主题 / 快捷键 / 通知三大横切系统**（`src/theme/`、`src/shortcuts/`、`src/notifications/`）；
4. **UI 组件与设计令牌**（`src/components/`、`src/shared/`、`src/styles/`）。

它的健康度直接决定 10 个下游项目的重复代码量与体验一致性——**库的价值以"下游真实 import"计量，而非以代码行数计量**。

## 二、一句话现状（基线事实）

**共享机制事实上已失效**：10 个下游项目全部通过 `file:../z-biz-tool-shared` 符号链接声明了依赖，但全仓库范围内只有 1 处真实 import（`z-biz-tool-file/src/agent/AgentPanel.tsx:17`）；9 个项目各自复制了一份完全相同的 6 文件 `src/agent/` 目录；`z-biz-tool-db/src/App.tsx:49` 留有注释"使用本地 Agent 组件（临时方案，待共享库修复后迁移到 z-biz-tool-shared）"——下游明确在等这个库修复。详细证据见 [01_现状审计与问题清单](./01_现状审计与问题清单.md)。

根因是三重的：

- **分发形态缺失**：`package.json` 无 build 脚本、无 `exports`，`main`/`types` 直指 `src/index.ts` 源码，`dist/` 仅含 tsbuildinfo（`tsconfig` 同时设 `noEmit:true` 与 `declaration/composite:true`，配置自相矛盾）；
- **文档与现实脱节**：INTEGRATION_GUIDE 宣称的 `new AIManager(...)`、`AIManagerProvider`、`useAIContext` 等 API 在源码中不存在；DEV_GUIDE / examples 使用的子路径 `z-biz-tool-shared/ai` 按当前包结构无法解析；IMPLEMENTATION_SUMMARY 宣称"terminal/aigen 集成 ✅、测试 ✅"，实际两个项目零引用、仓库零测试；
- **API 面与设计系统内部重复冲突**：两套主题系统（`src/theme/` 十主题 vs `src/shared/ThemeContext` 明暗两态）、三套设计令牌、两套快捷键体系，顶层 `src/index.ts` 靠 `export *` + 手工白名单规避重名冲突。

## 六、核心原则（全套方案共用）

1. **API 面向下游稳定**：导出面即契约，任何新增/删除/改名都走 API 报告 diff 审查；
2. **破坏性变更必须有迁移路径**：弃用标注 → 迁移指南条目 → 至少一个 minor 周期缓冲 → major 删除；
3. **凭据不入包**：`apiKey` 等敏感配置只允许运行时注入，发布产物与文档示例中不得出现真实密钥形态字符串；
4. **类型契约完整**：公共 API 无 `any`、无未导出的关联类型，下游 `tsc --noEmit` 可独立通过。
