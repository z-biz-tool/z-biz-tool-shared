## 二、下游集成现状（库的核心 KPI）

10 个下游项目 `package.json` 均声明 `"z-biz-tool-shared": "file:../z-biz-tool-shared"`（`node_modules/z-biz-tool-shared` 实测为符号链接 → `../../z-biz-tool-shared`）。但真实源码引用情况如下：

| z-biz-tool-db | ✅ | ❌ 0 处 | ✅ 有 | `../../z-biz-tool-db/src/App.tsx:49` 注释"临时方案，待共享库修复后迁移" |

| z-biz-tool-sys | ✅ | ❌ 0 处 | ✅ 有 | — |

| z-biz-tool-agent-worker | ✅ | ❌ 0 处 | 未统计 | — |

**结论（已确认缺陷）**：跨全仓库对 `z-biz-tool-shared` 的真实源码 import 仅 **1 处**（file 项目），且用的是深路径 `z-biz-tool-shared/src/agent/AgentManager`（绕过包入口，依赖 `src` 直连，一旦改 `main`/`exports` 即断裂）。9 个项目各自维护一份逐字节相同的 `src/agent/`（`AgentManager.ts`/`AgentPanel.tsx`/`QueryHistoryViewer.tsx`/`SQLEditor.tsx`/`types.ts`/`index.ts`）——**这正是共享库本应消灭的重复**。db 的注释直接证明：下游知道有共享库、想用、但"待修复"。

> `db/vite.config.ts:10` 另配了 alias `"z-biz-tool-shared": path.resolve(__dirname, "../z-biz-tool-shared/src")`，说明 db 曾尝试直连源码但当前 src 内已回退到本地复制。alias 指向 `src` 而非包入口，与 file 的深路径 import 是同一类"绕过包契约"的临时手法。

## 三、已确认缺陷（源码级证据）

### A-1 无编译产物，包不可被正常解析消费（P0）
`main`/`types` 指向 `src/index.ts`（[`../../package.json:6-7`](../../package.json)），`dist/` 仅有 tsbuildinfo 无 `.js`/`.d.ts`。下游要么走符号链接直连 TS 源码（依赖各自 vite 编译 node_modules 内的 .tsx，脆弱），要么复制源码（现状）。**这是共享失效的技术根因。**

### A-2 tsconfig 自相矛盾，declaration/composite 永不产出（P0）
[`../../tsconfig.json`](../../tsconfig.json) 同设 `noEmit:true`(L12) 与 `declaration:true`(L21)、`declarationMap:true`(L22)、`composite:true`(L24)、`outDir:"dist"`(L23)。`noEmit` 使 `tsc` 不产出任何 `.d.ts`/`.js`，`composite` 只生成 tsbuildinfo。类型产物能力形同虚设。

### A-3 顶层导出面靠 `export *` + 手工白名单，重名冲突未根治（P0）
[`../../src/index.ts`](../../src/index.ts) 对 8 个模块 `export *`（L2-9），并注释承认"shared 模块与 theme/components 存在重名成员（ThemeProvider/useTheme、EmptyState）"（L11-12），只能对 shared 显式挑选无冲突部分导出（L13-36）。这意味着：`ThemeProvider`/`useTheme`/`EmptyState` 存在**多个来源**，顶层导出的到底是哪一个由书写顺序决定，下游无法预期。导出面不稳定 = API 契约不存在。

### A-4 两套主题系统并存且互不兼容（P1）
- `src/theme/`：10 主题（dark/light/dracula/solarized/tokyoNight/nord/oneDark/monokai/ayu/gruvbox），基于 zustand `useThemeStore`，`useTheme` 返回 `{currentTheme, themeColors, setTheme}`（[`../../src/theme/ThemeContext.tsx:9-13`](../../src/theme/ThemeContext.tsx)、[`../../src/theme/themeManager.ts:5-126`](../../src/theme/themeManager.ts)），localStorage 键 `'theme'`。
- `src/shared/ThemeContext.tsx`：仅 light/dark 两态，`useTheme` 返回 `{mode, toggle}`（[`../../src/shared/ThemeContext.tsx:5-8`](../../src/shared/ThemeContext.tsx)），localStorage 键 `'z-tool-theme-mode'`，且强依赖 antd（L2）。

两者 `useTheme` 返回结构完全不同、localStorage 键不同、依赖不同。INTEGRATION_GUIDE 示例用 `themeColors`(L117)，[`../../src/shared/README.md:232`](../../src/shared/README.md) 示例用 `const { mode } = useTheme()`——**下游按哪份文档写都会踩空**。

### A-5 三套设计令牌并存（P1）
- [`../../src/styles/designTokens.ts`](../../src/styles/designTokens.ts)：`COLORS`/`SPACING`/`BORDER_RADIUS`/`SHADOW`…（大写下划线，值为数字/字符串混合，L15-133）；
- [`../../src/shared/designTokens.ts`](../../src/shared/designTokens.ts)：`radius`/`shadow`/`size`/`motion`/`gradient`/`colors`（小写，`as const`，L6-51）；
- [`../../src/components/UIDesignSystem.tsx:10-54`](../../src/components/UIDesignSystem.tsx)：`DESIGN_TOKENS.borderRadius/boxShadow/spacing/fontSize`（值为 `'4px'` 字符串）。

同一概念（圆角/阴影/间距）三种命名、三种值类型（number vs `'4px'` string）。INTEGRATION_GUIDE 宣称统一入口是 `DESIGN_TOKENS`(L72/L238)，shared/README 宣称是 `radius/shadow`(小写)——令牌系统本身就不统一。

### A-6 文档 API 与源码严重不符（P0，可信度问题）
[`../../INTEGRATION_GUIDE.md`](../../INTEGRATION_GUIDE.md) 宣称并示例的以下 API **在 src 中不存在**：
- `new AIManager({apiKey, models})`（L84）、`AIManagerProvider`（L81/L93）、`useAIContext()`（L98）、`generateText/generateCode/translate`（L98/L100）——源码实际导出的是 zustand hook `useAIManager`（[`../../src/ai/AIManager.ts:147`](../../src/ai/AIManager.ts)），无 class `AIManager`、无 Provider、无 `useAIContext`；
- API 文档表（L346-357）列 `generateText/generateCode/translate/summarize/optimize/explain/review` 方法，实际 `useAIManager` 只有 `executeAI/executeWithAgent/getModels/setConfig/updateConfig/setContext/addAgent/removeAgent`（[`../../src/ai/AIManager.ts:132-144`](../../src/ai/AIManager.ts)）；
- `useShortcut`/`useGlobalShortcut`（L126/L137）确在 `GlobalShortcutHandler.tsx` 存在，但 INTEGRATION_GUIDE 与 DEV_GUIDE 对 shortcut API 的描述（`register(category,id,config)` vs `register(category,key,config)`）不一致。

[`../../IMPLEMENTATION_SUMMARY.md`](../../IMPLEMENTATION_SUMMARY.md) 宣称"terminal 集成 ✅、aigen 集成 ✅、替换 useAIStore 为 useAIManager ✅"（L92-114），但实测 terminal/aigen 源码中 `useAIManager` 引用数 = **0**，`useAIStore` 仍存在。宣称"功能测试 ✅ / 兼容性测试 ✅"（L224-239），但仓库**无任何测试文件/测试框架依赖**。

### A-7 examples 全部无法编译（P0，DX 问题）
5 个 example 均 import `z-biz-tool-shared/ai`、`z-biz-tool-shared/notifications`、`z-biz-tool-shared/theme`、`z-biz-tool-shared/shortcuts`（[`../../examples/AIExample.tsx:6-7`](../../examples/AIExample.tsx) 等）。但：① 包无 `exports` 字段，子路径 `/ai` 无对应目录产物；② examples 不在 tsconfig `include:["src/**/*"]`（[`../../tsconfig.json:29`](../../tsconfig.json)）内，永不 typecheck；③ DEV_GUIDE 宣称 `npm run dev` 运行示例（L54），但 package.json 无 dev 脚本、examples 无入口 HTML/vite 配置。**示例是"看起来能用"的死代码。**

### A-8 ThemeSelector 死代码 / setState 时序缺陷（P2）
[`../../src/shared/ThemeContext.tsx:118-195`](../../src/shared/ThemeContext.tsx)：`items` 数组（L122-159）中 onClick 调用 `setModeInternal`，但该 state 在 L161 才声明（`const [internalMode, setModeInternal] = useState(mode)` 在 items 之后），且 `internalMode` 从未被读取；点击"跟随系统/亮色/暗色"只改了一个未使用的内部 state，**不会真正切换 `ThemeProvider` 的 mode**。该组件当前无法工作。

### A-9 大量 mock/stub 混入公共 API（P1）
- [`../../src/agent/AgentManager.ts`](../../src/agent/AgentManager.ts)：`query`/`optimize`/`analyze`/`diagnoseError` 四方法全部是 `// TODO: 调用 Agent 服务`（L40/L77/L114/L151）的假实现，`optimize` 甚至用 `sql.toUpperCase()` 充当"优化建议"（L81）；
- [`../../src/interactions/interactionPatterns.ts:98-120`](../../src/interactions/interactionPatterns.ts)：`InteractionFeedback.toast.showSuccess/…` 全是空函数体 `() => {}`；
- [`../../src/ai/context.ts:60-78`](../../src/ai/context.ts)：`loadFromFile`/`loadFromKnowledgeBase` 仅 `console.log` 占位。
- [`../../src/agent/QueryHistoryViewer.tsx:32`](../../src/agent/QueryHistoryViewer.tsx)：`loadHistory` TODO，history 恒为空数组（L22）。

这些 stub 通过 `export *` 进入公共 API，下游无法区分"真能力"与"占位"。

### A-10 AIConfig.timeout 声明但从未使用（P2）
[`../../src/ai/types.ts:29`](../../src/ai/types.ts) 定义 `timeout?: number`，[`../../src/ai/AIManager.ts:153`](../../src/ai/AIManager.ts) 默认设 `timeout:30000`，但 `OpenAIClient.chat` 的 `fetch`（L28-40）**无 AbortController / 无超时控制**，timeout 是无效配置项，误导下游以为有超时保护。

### A-11 provider 工厂退化为单一 OpenAI（P2）
[`../../src/ai/AIManager.ts:228-236`](../../src/ai/AIManager.ts) `createClient` 对 `'claude'|'gemini'|'ollama'|'local'` 全部走 `default` 返回 `OpenAIClient`。DEV_GUIDE 宣称"多提供商支持 OpenAI/Claude/Gemini/Ollama"（L66）与实现不符。`executeWithAgent` 硬编码 `provider:'local'`（L209）却仍拿到 OpenAIClient，语义矛盾。

### A-12 通知 id 生成与定时器不安全（P2）
[`../../src/notifications/notificationManager.ts:16`](../../src/notifications/notificationManager.ts) 用 `Math.random().toString(36).substring(2,9)` 生成 toast id（碰撞可能），`setTimeout`（L29）无句柄保存，`clearToasts`（L43）不清除已挂起的定时器 → 组件卸载后仍可能触发 `removeToast`（对已清空 store 无害但不严谨）。

### A-13 `any` 与 console 散落（P1，类型质量）
`src` 下 `any` 出现 **8 处**（AgentPanel/AgentManager/SQLEditor/CollapsiblePanel/Omnibar/AIManager），`console.*` **7 处**。公共方法签名如 `analyze(sql, results: any)`（[`../../src/agent/AgentManager.ts:12`](../../src/agent/AgentManager.ts)）、`SQLEditorProps.onExecute?: (sql)=>Promise<any>`（[`../../src/agent/SQLEditor.tsx:9`](../../src/agent/SQLEditor.tsx)）直接暴露 any 给下游，破坏类型契约。

### A-14 localStorage 键命名空间不统一（P2）
主题相关键有 `'theme'`（[`../../src/theme/themeManager.ts:146`](../../src/theme/themeManager.ts)）与 `'z-tool-theme-mode'`（[`../../src/shared/ThemeContext.tsx:15`](../../src/shared/ThemeContext.tsx)）两套。多个 Tauri 应用若同源可能互相污染；`'theme'` 这种通用键名尤其危险。
