## 一、测试分层策略

对标成熟 TS 库的分层测试理念（vitest + @testing-library + api-extractor，理念对标非复制），针对库项目特点分五层：

| 层 | 对象 | 工具（规划） | 关注 |
|----|------|-------------|------|
| **L1 单元** | 纯逻辑模块：AIManager/themeManager/shortcutManager/notificationManager/tokens | vitest | 状态转换、边界、纯函数 |
| **L2 组件/集成** | React 组件：AgentPanel/ToastContainer/ThemeProvider/AppShell | vitest + @testing-library/react + jsdom | 渲染、交互、provider 契约 |
| **L3 API 契约** | 公共导出面 + `.d.ts` | api-extractor 报告 diff + 类型断言测试 | 导出面稳定、类型完整 |
| **L4 发布/构建** | dist 产物、exports 解析、files 白名单、secret 扫描 | tsup build + 解析脚本 + npm pack --dry-run | 产物可被下游解析、凭据不入包 |
| **L5 性能/体积** | 各子路径 bundle 体积、tree-shaking 有效性 | size-limit / rollup-plugin-visualizer | 体积预算、按需引入不拖入 antd |

### 1.1 夹具（fixture）与隔离原则

- **无真实网络**：AIManager 的 `fetch`（[`../../src/ai/AIManager.ts:28`](../../src/ai/AIManager.ts)）在测试中用 mock/stub 拦截，**绝不发真实 API 请求、绝不使用真实 apiKey**（联动 [04 §5.2](./04_稳定性兼容与发布安全.md)）；
- **localStorage 隔离**：主题/通知依赖 localStorage（[`../../src/theme/themeManager.ts:146`](../../src/theme/themeManager.ts)、[`../../src/shared/ThemeContext.tsx:15`](../../src/shared/ThemeContext.tsx)），每用例前 `clear()`，避免键 `'theme'`/`'z-tool-theme-mode'` 跨用例污染（[01 A-14](./01_现状审计与问题清单.md)）；
- **store 单例隔离**：zustand store 是模块级单例（`useAIManager`/`useThemeStore` 等），用例间需重置 state（`store.setState(initial)`），否则状态泄漏；
- **定时器可控**：notificationManager 用 `setTimeout`（[`../../src/notifications/notificationManager.ts:29`](../../src/notifications/notificationManager.ts)），测试用 `vi.useFakeTimers()`；
- **matchMedia mock**：`initTheme`/ThemeProvider 用 `window.matchMedia`（[`../../src/theme/themeManager.ts:171`](../../src/theme/themeManager.ts)），jsdom 需注入 mock；
- **每个测试文件独立可运行**，不依赖执行顺序。
