## 一、语义化版本策略

### 1.1 现状版本治理缺失

[`../../package.json:3-5`](../../package.json)：`version:"0.1.0"` + `"private":true`。`private:true` 意味着 npm 拒绝发布（防误发），但也表明当前**无版本发布流程**——下游靠 `file:` 符号链接直连源码，任何一次 commit 立即影响全部 10 个下游，没有版本缓冲。git 历史仅 4 commit（`git log` 实测），无 tag、无 CHANGELOG。

### 1.2 推荐版本策略（唯一方案）

采用 **SemVer 2.0**，在 workspace/私有分发下仍以版本号作为下游锁定的契约锚点：

| 版本位 | 触发条件 | 示例 |
|--------|----------|------|
| **MAJOR** | 删除/重命名公共 API、改变 API 行为语义、类型不兼容变更 | 移除 `src/theme` 旧 `useTheme` 返回结构 |
| **MINOR** | 新增子路径/新增导出符号（向后兼容）、新增可选参数 | 新增 `z-biz-tool-shared/tokens` |
| **PATCH** | bug 修复、内部重构、不改 API 面 | 修复 ThemeSelector 死代码（[01 A-8](./01_现状审计与问题清单.md)） |

配套：① 引入 `changesets`（或 `standard-version`）管理版本与自动生成 CHANGELOG；② 每次发布打 git tag `v{version}`；③ `0.x` 阶段约定 minor 亦可能含破坏性变更（SemVer 对 0.x 的惯例），需在 README 明示，直至 API 稳定后升 `1.0.0`。

### 1.3 是否解除 `private:true`

- 若走**私有 registry 发布**（[03 §5 方式C](./03_架构与工程化优化.md)）：需移除 `private:true`，配 `.npmrc` 指向私仓；
- 若走 **workspace/file-link**（推荐近期终态，[03 §5](./03_架构与工程化优化.md)）：保留 `private:true`，版本号仅作下游锁定与 CHANGELOG 锚点，不实际 publish。
- **推荐**：近期保留 `private:true` + workspace，避免过早引入 registry 运维负担；版本号照常递增以维护契约纪律。

## 二、file-link 同步风险与缓解

### 2.1 风险本质

`file:../z-biz-tool-shared` 是符号链接（`node_modules/z-biz-tool-shared -> ../../z-biz-tool-shared`，实测）。其后果：

- **提交即发布**：库的任意改动（含未过测试的）立即对所有下游可见，无版本闸门；
- **构建态不一致**：下游直连 `src` TS 源码时，各自 vite 独立编译库代码，同一份库在不同下游可能因 vite 配置差异产出不同行为（[01 H-1](./01_现状审计与问题清单.md)）；
- **无回滚点**：库 HEAD 前进后，下游无法锁定到"上一个可用版本"，除非用 git tag + 精确 file 引用。

### 2.2 缓解措施（推荐组合）

1. **库预构建 + 下游消费 dist**：下游经 `exports` 拿 `dist` 产物而非 src（[03 §4/§5](./03_架构与工程化优化.md)），构建态唯一；
2. **CI 门禁**：库的每次改动必须先过自身 typecheck/lint/build/test + **下游集成回归**（[06 §3](./06_测试验收与风险清单.md)）才允许合入 main；
3. **版本 tag 锚点**：破坏性变更合入前打 tag，下游可在过渡期锁定旧 tag；
4. **watch 联调规范**：本地开发用 `tsup --watch`（[03 §2.1](./03_架构与工程化优化.md)）+ 下游 vite dev，避免手改 dist。

## 三、破坏性变更与迁移管理

### 3.1 破坏性变更识别清单（本篇方案将产生的）

[02](./02_API设计与开发者体验.md)/[03](./03_架构与工程化优化.md) 的收敛动作中，以下属**破坏性**，须走迁移流程：

| 变更 | 破坏性 | 影响下游 | 迁移 |
|------|:---:|----------|------|
| `useTheme` 返回结构归一（theme vs shared 二选一，[02 §2.3](./02_API设计与开发者体验.md)） | 是 | 用到 `mode`/`toggle` 或 `themeColors`/`setTheme` 的组件 | 提供兼容层：新 `useTheme` 同时暴露 `{mode, toggle, themeColors, setTheme, currentTheme}` 一个 minor 周期，再拆分 |
| 三套令牌收敛为一套（[02 §4](./02_API设计与开发者体验.md)） | 是 | 引用 `COLORS`/`DESIGN_TOKENS.borderRadius` 的样式代码 | 旧令牌名 `@deprecated` re-export 到新令牌，保留一个 minor |
| 子路径导入取代 `src` 深路径（[03 §5](./03_架构与工程化优化.md)） | 是 | file 项目 `z-biz-tool-shared/src/agent/AgentManager` | 迁移脚本改为 `z-biz-tool-shared/agent`；过渡期 exports 保留 `./src/*` 兼容映射并告警 |
| `InteractionFeedback` 移出公共 API（[02 §5](./02_API设计与开发者体验.md)） | 是（若有人用） | 实测 0 引用，风险低 | 直接移除，标注于 CHANGELOG |
| `shared/` 目录取消（[03 §1.2](./03_架构与工程化优化.md)） | 是 | 直连 `shared` 的深路径导入 | 内容分流到 theme/components/tokens，旧路径 re-export 过渡 |

### 3.2 迁移流程（强制四步）

对标成熟库的 deprecate-then-remove 纪律（理念对标，非复制）：

1. **标注**：破坏性变更前一个 minor，旧 API 加 `@deprecated` JSDoc + 运行时 `console.warn`（一次性，避免刷屏）；
2. **文档**：在 [`../../MIGRATION_GUIDE.md`](../../MIGRATION_GUIDE.md) 追加"旧→新"对照条目（该文件已有 `useAIStore→useAIManager` 表结构，[L159-165](../../MIGRATION_GUIDE.md)，可复用模板）；
3. **缓冲**：至少保留一个 minor 周期（或一个 sprint），期间新旧并存；
4. **移除**：MAJOR 版本删除旧 API，CHANGELOG 明列，迁移指南给出 codemod/查找替换指引。

### 3.3 MIGRATION_GUIDE 现状修正

现有 [`../../MIGRATION_GUIDE.md`](../../MIGRATION_GUIDE.md) 描述的 terminal/aigen 迁移（L5-88）以"新版代码"口吻呈现，但实测 terminal/aigen 源码零引用 `useAIManager`（[01 A-6](./01_现状审计与问题清单.md)）——迁移**尚未发生**。修正为"待执行迁移剧本"，并补充本篇 §3.1 的库自身破坏性变更迁移条目。

## 四、下游多项目兼容矩阵

10 个下游同时依赖，版本/依赖漂移是主要兼容风险。基于实测依赖版本（[01 §二](./01_现状审计与问题清单.md)）：

| 下游 | react | antd | zustand | typescript | 兼容关注点 |
|------|-------|------|---------|-----------|-----------|
| db/file/knowledge/terminal/sys/box/aigen/agent-worker | ^19.0.0 | ^6.0.0 | ^5.0.0 | ^5.6.0 | 基线一致，peer 范围 `>=18<20`/`>=5<7` 覆盖 |
| note | ^19.0.0 | 未列(用 @ant-design/icons ^6.0.0) | 未列 | ^5.6.0 | antd 为 optional peer 才不报错 |
| **pet** | **^19.2.5** | **^6.5.3** | **^5.0.12** | **^6.0.3** | ts 6 与库 dev 的 ts 5.7 不同；antd minor 更高——需验证 d.ts 兼容（[01 H-4](./01_现状审计与问题清单.md)） |

**兼容策略**：
1. peer 用**宽范围**（[03 §3.1](./03_架构与工程化优化.md)）吸收 minor 漂移；
2. antd/icons/codemirror 标 **optional peer**，兼容 note 这类不装 antd 的下游；
3. **最低支持版本**明确写入 README（react≥18、ts≥5.6、antd≥5），pet 的 ts6 属超前，需在 CI 增加 ts6 编译矩阵验证；
4. 每次 MINOR/MAJOR 发布前跑**下游集成回归**（[06 §3](./06_测试验收与风险清单.md)），10 项目 typecheck + 关键项目 build 全绿方可发布。

## 五、发布流程与供应链、凭据安全

### 5.1 发布产物白名单（凭据不入包的结构性保障）

`files:["dist"]`（[03 §4.1](./03_架构与工程化优化.md)）确保**只有编译产物入包**，源码/examples/doc/`.env`/配置文件一律不进 tarball。发布前用 `npm pack --dry-run` 核对文件清单（规划纳入发布脚本，本次不执行）。

### 5.2 凭据与密钥不入包（P0 安全）

- **现状风险**：`AIConfig.apiKey`（[`../../src/ai/types.ts:24`](../../src/ai/types.ts)）是运行时配置字段，MIGRATION_GUIDE 示例出现 `apiKey:"sk-..."` 形态字符串（[`../../MIGRATION_GUIDE.md:131`](../../MIGRATION_GUIDE.md)、INTEGRATION_GUIDE `apiKey:'your-api-key'` [L85](../../INTEGRATION_GUIDE.md)）——**当前为占位符非真实密钥**，但文档示范了"把 apiKey 写进代码"的反模式。
- **推荐约束**：
  1. 库**绝不硬编码任何真实密钥**；`apiKey` 只经运行时 `updateConfig` 注入，来源为下游的安全存储（Tauri 侧 secret / 环境变量），文档示例统一用 `<YOUR_API_KEY>` 占位并加"勿硬编码"警示；
  2. 发布前 **secret 扫描**：对 `dist` 与待发布文件跑密钥模式扫描（如 `sk-`、`Bearer `、私钥头等），命中即阻断发布；
  3. `.gitignore`（[`../../.gitignore`](../../.gitignore)）补充 `.env`、`*.pem`、`*.key`（现状仅 node_modules/dist/*.log/.DS_Store，未覆盖 env/密钥文件）；
  4. AIManager 的 `fetch` 走 `Authorization: Bearer ${apiKey}`（[`../../src/ai/AIManager.ts:32`](../../src/ai/AIManager.ts)），需确保 apiKey 不被日志打印（现有 7 处 console，[01 A-13](./01_现状审计与问题清单.md)，审计是否泄漏 config）。

### 5.3 供应链安全

- **锁文件**：`package-lock.json`（112KB）纳入版本控制，保证可复现安装；
- **依赖审计**：CI 加 `npm audit`（高危阻断）；
- **peer 范围下限**不过旧，避免拉入含漏洞的历史版本；
- **构建可复现**：tsup 版本锁 devDependencies，CI 用 `npm ci`（非 `npm install`）；
- **最小依赖面**：清理幽灵依赖 immer/codemirror（[03 §3.2](./03_架构与工程化优化.md)）直接缩小供应链攻击面。

### 5.4 发布流程（推荐 SOP，规划未执行）

```
1. 变更归类（changeset）→ 决定 MAJOR/MINOR/PATCH
2. 本地：clean → typecheck → lint → build → test（全绿）
3. API 报告 diff 审查（导出面变化必须显式，联动 03 §6.3）
4. 破坏性变更？→ 确认已过 §3.2 四步迁移流程 + MIGRATION_GUIDE 已更新
5. npm pack --dry-run → 核对 files 白名单（仅 dist）
6. secret 扫描 dist → 无命中
7. 下游集成回归（06 §3）→ 10 项目 typecheck + 关键 build 全绿
8. bump version → 生成 CHANGELOG → git tag v{version}
9. 发布 / 更新 workspace 版本锚点
```
